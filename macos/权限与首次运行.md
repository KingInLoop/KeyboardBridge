# macOS 安装、权限与首次运行

v0.2.10 使用标准安装包将应用固定安装到 `/Applications/KeyboardBridge.app`，并修复临时签名升级后旧授权条目与当前应用身份不一致的问题。macOS 仍要求用户亲自确认隐私权限，应用不能也不会绕过这一机制。

1. 双击 `KeyboardBridge-macOS-v0.2.10.pkg` 并完成安装。安装器会覆盖经 bundle id 校验的旧版，固定写入 `/Applications/KeyboardBridge.app`，然后自动启动。
2. 点击“授权键盘输入（辅助功能）”，在打开的“系统设置 → 隐私与安全性 → 辅助功能”中允许 KeyboardBridge。此权限用于向当前聚焦位置发送按键。
3. 点击“授权复制监听（输入监控）”，在打开的“系统设置 → 隐私与安全性 → 输入监控”中允许 KeyboardBridge。此权限用于监听其他应用中的 `Command+C` 和停止快捷键。
4. 每次点击后，应用会在 0.8、2 和 5 秒自动复查对应权限。
5. 必要时完全退出后重开。仅关闭窗口不会退出；请从菜单栏图标选择“退出”。
6. 确认权限状态均为绿色“已授权”。

## 开关已开启但仍显示未授权

先点击权限状态旁的“刷新状态”。应用平时也会每 0.5 秒自动检测，并在输入监控刚获批时自动重建复制监听器。

若系统仍返回未授权，界面才会展开“清理旧授权记录并重新授权”。常见原因是旧版与新版都使用临时签名：每次重新构建都会产生新的代码身份，系统设置中的旧开关虽然仍然显示开启，却不属于当前二进制。点击该入口并确认后，应用会执行：

1. 仅重置 bundle id `local.keyboardbridge.app` 的辅助功能记录。
2. 仅重置该 bundle id 的输入监控记录。
3. 重新打开辅助功能设置，引导依次完成两项授权。

v0.2.10 安装器检测到临时签名时也会在启动新版前自动执行上述清理。若使用稳定的 Developer ID 签名，升级不会清理权限，已有授权可以继续沿用。两项授权成功后，清理入口会自动收起。

固定安装路径可以避免从下载目录、解压目录或多个副本运行时授权对象不一致。安装器还会清理 bundle id 相同的 `~/Applications` 历史副本；不会删除无法确认身份的同名应用。

未使用 Developer ID 签名和公证的开发包，首次安装仍可能出现“Apple 无法验证”。请在 Finder 中右键安装包并选择“打开”；不要全局关闭 Gatekeeper。面向其他用户发布时，应使用构建脚本的 Developer ID Application、Developer ID Installer 与自动公证功能。
